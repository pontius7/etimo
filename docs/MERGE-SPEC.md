# MERGE SPEC: Etimo (base) + Devter

Read-only analysis. No input file was modified.
Offsets are 0-based character offsets into the whole HTML file. "line" is the 1-based line number.
E = Etimo index.html (957 KB). D = Devter index.html (829 KB).
Full artifact trees (data, modules) are at `scratchpad/artifact-files/2ecc40c6-.../` (Etimo) and `.../db484244-.../` (Devter).
Helper scripts in `scratchpad/`: g.py (grep with offsets), proj.py (conic forward/inverse), cssdiff.py, ov.py.

## 0. Headline findings

1. Same engine, same lineage. Both are React 19 + d3 SVG maps with identical CSS ids v41..v62 and an identical UI-language set (`en`, `sr`, `sc` = Serbian Cyrillic generated by transliteration, `sq`, `de`). Both use `localStorage` keys `khl-*`.
2. Etimo already contains the dormant Devter overlay code. The adm2 district layer (`d2m`/`adm2l` classes), micro places, ethnic composition panel and topo layer all exist in the Etimo bundle. They are disabled by three stub loaders that return `Promise.resolve(null)` (section 3). Enabling them is a loader patch, not a code port.
3. The projection is data-fitted. `fitExtent` over the language points sets scale and translate at runtime. Only `parallels`, `rotate` and the pre-projected assets are fixed: `dia.json`, `terr.json`, `shade.webp` and (Devter only) `topo.json`. They live in a "reference frame" (conic conformal at scale 1000, translate 0). The two apps use different frames, so Devter's `terr` and `dia` must be re-projected into the merged frame (a regex on M/L/Z paths).
4. Zero overlap between the two language sets. 0 shared `lang` names, 0 shared glottocodes, 0 shared id slugs, and the family and path-root names are disjoint. A merge is a pure union.
5. Most work is mechanical and data-driven. A few surgical patches in the Etimo bundle are needed: family arrays and maps, UI strings, stubs, two projection constants, the shade/translateExtent box, and wheel font sizes.

### 1.2 Can one projection cover both regions?

Yes, geometrically. Conic conformal handles lon -8 to 134 and lat 26 to 73. These are the language-point extents from `languages.json`: Etimo lon -8.1 to 75.1, lat 26.2 to 59.0; Devter lon 13.7 to 134.0, lat 28.3 to 73.1.

Scale-factor spread (max/min k over all 209 language points):

| frame | k ratio |
|---|---|
| Etimo [35,60] rot -30 (current) | 1.14 |
| Devter [42,66] rot -72 | 1.11 |
| [38,64] rot -60 | 1.10 |
| [36,66] rot -60 | 1.09 |
| [40,66] rot -65 | 1.11 |

So scale distortion is small in every case. The real tradeoff is rotation ("north tilt") = n * (lon - central meridian):

- Etimo frame (n=0.743, central 30E): Balkans (20E) about -7 degrees, Caucasus (45E) +11 degrees, Yakutia (130E) +74 degrees, Mongolia (105E) +56 degrees.
- A new central 60E frame (n about 0.79): Balkans -31 degrees, Siberia +55 degrees. This visibly changes Etimo's home region.

Option K (keep the Etimo frame) is recommended. It leaves every Etimo asset untouched. Option N (new frame) requires re-projecting all Etimo `dia`/`terr` and regenerating the raster.

Option K. Keep `parallels([35,60]).rotate([-30,0])`:
- Etimo's `shade.webp`, `dia.json`, `terr.json`, `lf`, the image attrs and the translateExtent box stay valid.
- All 131 Devter language points fall inside the existing raster box (checked: 0 outside).
- Of Devter's 83 terr polygons, only `Yakut` (551 of 813 vertices) falls outside the raster box. The raster top edge is at lat 72.5 at 130E and the box ends near 140E at lat 60. Of Devter's dia vertices, 535 of 8478 are outside.
- Needed: re-project Devter `terr.json` and `dia.json` into the Etimo frame. No raster regeneration is required. Optionally extend the raster north-east, which needs a DEM plus Etimo's styling pipeline (not available; see 1.3).
- Siberian shapes appear rotated clockwise. The merged initial `fitExtent` zooms out (Balkans to Yakutia) so the Balkans start smaller. Optional patch P-fit (section 6) fits only Etimo-region points initially.
- The mini-map `wf` (E off 778814) uses the same fixed `rotate([-30,0])`. For Devter languages at 100E+ it would tilt. Patch to `rotate([-(o.lon),0])`. Devter itself uses -60 for its mini-map vs -72 for the main map, so per-language rotation is consistent with Devter's practice.

Option N (only if Siberia must look upright). Choose for example `parallels([36,66]).rotate([-60,0])` (k ratio 1.09). Then:
1. Replace the constants at E off 866713 and E off 778814.
2. Re-project ALL pre-projected assets: Etimo `terr` (185 KB), `dia` (285 KB) and Devter's (see 1.3).
3. Regenerate or warp `shade.webp` and update its image x/y/w/h (E off 871193), the translateExtent literals (E off 911943) and optionally the unused `lf`.
4. Etimo's raster can be warped pixel-wise from the old frame (no DEM needed) for the area it already covers. It does not cover NE Siberia, so this still needs a DEM-based hillshade for the missing area.

### 1.3 Re-projection recipe (data-level, exact)

Frame forward (d3 conicConformal, scale 1000, translate 0):

```
n = ln(cos φ0 / cos φ1) / ln(tan(π/4+φ1/2) / tan(π/4+φ0/2))
F = cos φ0 · tan(π/4+φ0/2)^n / n
ρ = F / tan(π/4+φ/2)^n
x = 1000·ρ·sin(n(λ+rot)),  y = -1000·(F - ρ·cos(n(λ+rot)))      (λ, φ in radians; rot = -30 or -72 degrees)
```

Devter frame to lon/lat to Etimo frame. Paths use only absolute `M`, `L`, `Z` with 1 decimal, so a regex over `-?\d+\.?\d*` pairs suffices.

- `terr.json` (83 Devter langs, 147 KB of path text): `{Lang:{d, a (area km2), b [x0,y0,x1,y1] bbox}}`. Re-project `d`, and recompute `b` from the new points. `a` is unchanged.
- `dia.json`: `{fam:{Name:path}, lang:{Name:path}}`. Same re-projection. Union by key; there are no collisions (E fam: Slavic, Iranian, Greek, Romance; D fam: Uralic, Turkic; E lang 10, D lang 30).
- `topo.json` (Devter only): `{m, i, g, u:10, mpg}` are paths in frame*10 (`u:10`). Etimo's code at E off 873040 consumes the same structure via the `op()` stub. The topo layer is not part of Etimo's current look (the stub returns null), so skip it. If wanted later, inverse-project then forward-project with `u=10`, and regenerate the graticule `g`.
- Do not re-project `adm2.json` (TopoJSON in lon/lat, quantized, 920 districts) or `micro.json` (lon/lat place lists) or `ethno.json` (lon/lat polygon for South Ossetia plus census tables). They are projected at runtime via `path.projection`.
- Etimo modules `regional-layer.js`, `country-data.js` and `country-sources.js` all use the runtime projection (`path.projection()`) and lon/lat sources. They need no change for a projection swap.

## 5. Boot path

Etimo first render blocks on (E off 942560, line 993):

```
Promise.all(["data/lexicon.json","data/languages.json","data/world-50s.json"]
  .map(e=>fetch(e).then(t=>{if(!t.ok)throw Error(...);return t.json()}))
  .concat([fetch("data/terr.json").then(e=>e.ok?e.json():{}).catch(()=>({}))]))
  .then(([e,t,n,r])=>{ua=e,ca=n,...,da=r||{},...render(Up)})
```

- Blocking: `lexicon.json` (2.5 MB), `languages.json` (66 KB), `world-50s.json` (183 KB), `terr.json` (185 KB, failure-tolerant). A merged lexicon would be about 4.9 MB; consider gzip/brotli and a loading skeleton (the `<p class="boot">` already exists).
- Lazy after first render: `dia.json` (E off 788664), `today.json` (E off 870399, 3.0 MB), `world-50m.json` (E off 879325), `shade.webp` (E off 871139), plus the modules `regional-layer.js` (dynamic `import("./regional-layer.js?v=34")` at E off 870145), `country-data.js`, `country-sources.js` (module tags in line 995). The module fetches (regional boundaries and observations 34.8 MB, albanian/vlach/serbia/greece, borders-10m) come after.
- All fetch paths are fixed literals under `data/` (no base-URL config); Devter's identical in shape. So data files can be swapped in place: `lexicon`, `languages`, `terr`, `dia`, `today` (and `adm2/micro/ethno` once the stubs are patched). Everything keyed by language name is picked up automatically with no code change: tree and wheel (from `info.path`), A-Z index, search, map pins, voronoi fallback circles for languages without `terr`. These parts are hard-coded: the family list and colours, the region tabs, the taxonomy additions, the UI strings and the projection constants.
- Per-language derived state is built in the boot `.then`: `e.id="l-"+slug(lang)`, `e.info=languages[lang]||{}`, categories via `sa[meaning]||meaning` then `ia[...]`. A meaning with no category is searchable but absent from browse by category.
- Sort/index key at boot (E off 943127): `k=(t.lat||t.ipa||t.word).toLowerCase().normalize("NFD")...replace(/^[^a-zЀ-ӿͰ-Ͽ]+/,"")`. Devter's equivalent is `(t.lat||t.word)` with the range `a-zЀ-ӿႠ-ჿ` (Georgian instead of Greek). For the merge the range must include both Greek and Georgian (`Ͱ-ϿႠ-ჿ`). Note a latent Etimo behaviour: for Latin-script words with `ipa` and no `lat`, the A-Z key is the IPA string. Devter Latin-script words (once given `ipa`) would then sort under IPA letters instead of the spelling. Safer key: `t.lat||(Latin-only word ? t.word : t.ipa||t.word)`, or leave `lat` = the spelling for Devter Latin-script words.

## 6. Recommendation

### 6.1 Strategy

Option (a): data-level merge plus surgical patches to the Etimo bundle (about 20 small text patches). Do NOT reconstruct source (b).

Why (a):
- Etimo's code already contains the Devter overlay features behind stubs, and every data file is read through literal paths. About 90 percent of the work is data and string tables.
- The patches are all text replacements on the minified bundle (E lines 959 and 993) and the head/inline blocks. Etimo's visual design is preserved byte-for-byte outside the patch sites.
- Why not (b): there is no source (only the minified React 19 + d3 bundle, 650 KB + 90 KB of patched app code, in both apps). Reconstructing it means de-minifying about 130 KB of hand-patched code per app and re-deriving a build, which takes days and cannot preserve Etimo byte-for-byte. Cost is high, and risk is that it changes behaviour.

Execution plan:
1. Data build script (Python or Node, run once): union `lexicon`, `languages`, `terr`, `dia`; re-project Devter terr/dia (option K); merge `today.json`; precompute Devter `ipa`/`lat`; copy `gc` into Devter lexicon records.
2. Apply the bundle and CSS patches P1 to P20 below.
3. Verify with chrome-devtools screenshots: initial map, family chips, wheel, a language from each new family, Georgian words, dark mode, `sr`/`sc`/`sq`/`de`.

### 6.3 Top risks

1. Visual fit of nine families and eleven wheel roots. Wheel and chip sizes were tuned for five, the tree builder is data-driven but label sizes are literal (P21), the symbol set is limited to four d3 shapes plus one custom (P8), and the colour clashes (blue turk vs Greek, greens) need a design decision.
2. Re-projected data fidelity and map orientation. Devter `terr`/`dia` are re-projected with a straight vertex transform (fine, since paths are dense polylines with 1-decimal coordinates), but Siberian shapes sit at +74 degrees tilt in Etimo's frame and `Yakut` extends beyond the existing hillshade raster. Choosing option N later forces a raster regeneration. The initial `fitExtent` also changes the first view.
3. Enabling the dormant overlays (P17). Stub loaders must return exactly `{F, M, topo, E}`; the consumers were minified in a different build than Devter's loaders. Also `micro.json` `h`/`x` index into `adm2.json` features by array order. Test by selecting a Devter language, zooming above k=2.2 and opening its panel.

Smaller risks: the ~4.9 MB blocking lexicon; `today.json` union (quantized vs float TopoJSON); keeping 4 UI locales aligned (en/sr/sq/de, `sc` derived); the Devter IPA/transliteration precompute must be run with Devter's own functions (`aN`, `aE`, `aS`, `rq`) for identical output; Etimo's A-Z key uses IPA for Latin words.
